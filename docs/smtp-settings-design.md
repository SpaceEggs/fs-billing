# 邮箱设置页面设计

本文档写于 2026-11-05，是开发前的设计。目标：管理员能在后台配置 SMTP，改完不用登录服务器，也不用重启服务。

设计稿在 [Claude 画布](https://claude.ai/artifact/TmWL9xgtW2aLjsptJSqWAB)（私有链接，需要所有者分享）。

## 已决定

| #   | 问题       | 决定（用户，2026-11-05）                                           |
| --- | ---------- | ------------------------------------------------------------------ |
| 1   | 页面位置   | 系统告警分三个标签：告警列表、告警设置、邮箱设置。不加新的左侧导航 |
| 2   | 监测脚本   | `notify.sh` 继续用服务器上的单独配置，页面不管它                   |
| 3   | 谁能修改   | 所有管理员。靠操作日志追溯，不加角色权限                           |
| 4   | 服务商预设 | QQ 邮箱和自定义两项                                                |

`notify.sh` 不读数据库，是因为它要在数据库或 API 挂掉时发信。代价是换邮箱时两处都要改，页面和手册都要写明这一点。

## 范围

**放到页面：** 启用开关、服务器、端口、加密方式、账号、密码或授权码、发件人邮箱、站点地址。

**留在环境变量：** `SMTP_TIMEOUT_MS`、`MAIL_RATE_PER_MINUTE`、`MAIL_MAX_ATTEMPTS`、`ALERT_QUIET_MINUTES`。这些不是日常配置，改错会影响所有邮件。

**不做：** 多套 SMTP、按租户配置发件人、OAuth 登录邮箱、发件人名称（仍用现有常量）。

## 配置来源

Worker 每轮发信前读一次配置。`createMailTransport` 本来就每轮新建，所以改完下一轮生效，不用重启。

| `smtp_settings.managed` | `enabled` | 实际行为                             |
| ----------------------- | --------- | ------------------------------------ |
| false（升级后的默认）   | 不看      | 继续用环境变量。没配环境变量就不发信 |
| true                    | true      | 用页面保存的配置，**不再看环境变量** |
| true                    | false     | 不发信，邮件留在发件箱               |

第一次保存就把 `managed` 设为 true，页面上叫“改由页面管理”。升级本身不改变发信行为。没有“退回环境变量”的按钮，真要退回由运维改数据库，手册写明步骤。

## 数据

新迁移加单行表，形状照 `alert_settings`（布尔主键加 `CHECK (id)`、`version`、`updated_by`）：

| 列                                                 | 说明                                                      |
| -------------------------------------------------- | --------------------------------------------------------- |
| `managed`、`enabled`                               | 见上表，默认都是 false                                    |
| `host`、`port`、`secure`、`username`               | 可空。`managed` 且 `enabled` 时由约束保证 host、port 已填 |
| `password_ciphertext`                              | 密文，可空                                                |
| `mail_from`、`site_url`                            | 可空                                                      |
| `last_test_at`、`last_test_ok`、`last_test_result` | 最近一次测试。结果只存错误分类，不存服务器原始响应        |

RLS 与 `alert_settings` 相同（`app_is_operator()`）。没有 DELETE 权限。`最近成功发送` 从 `email_outbox` 的 `sent_at` 查，不另存。

## 密码加密

- AES-256-GCM，随机 96 位 IV，密文格式带版本前缀 `v1:`，AAD 固定为 `smtp_settings.password`。
- 密钥是新环境变量 `SETTINGS_ENCRYPTION_KEY`（32 字节，base64），放在 `app.env`，API 和 Worker 都读。不复用 `BETTER_AUTH_SECRET`，否则轮换登录密钥会连带解不开密码。
- `bootstrap-server.sh` 为新服务器生成。已有服务器按手册手工添加。
- 没配密钥时：页面能打开，保存和测试返回 `SETTINGS_KEY_MISSING`，页面说明要先配密钥。环境变量来源的发信不受影响。
- 解不开时（密钥换过或丢了）：Worker 记错误日志并不发信，邮件留在发件箱；页面显示“已保存的密码无法解密，请重新填写”。不静默回退到环境变量，否则会用错账号发信。

**备份：** 每日备份同时含数据库和 `/etc/fs-billing`，密文和密钥在同一套备份里。异地备份必须加密，这条现有手册已要求，这里再加一句说明原因。

## 接口

都在 `/api/admin/`，都要管理员身份。

| 操作         | 路径                      | 说明                                                                 |
| ------------ | ------------------------- | -------------------------------------------------------------------- |
| 读取         | `GET mail-settings`       | 不返回密码，只返回 `passwordSet`。附带来源、状态、环境变量的非秘密值 |
| 保存         | `PUT mail-settings`       | 带 `expectedVersion`，冲突返回 409，同告警设置                       |
| 发送测试邮件 | `POST mail-settings/test` | 用请求里的配置发送，不保存                                           |

`adminAlertSettings` 的 `mailEnabled` 改为从这份有效配置算，告警设置页的“未配置”提示才准确。

**校验：** 把 `refineMailEnvironment` 的规则抽出来，环境变量和页面共用，比如 465 只能隐式 TLS、587 和 25 只能 STARTTLS、QQ 的发件人必须等于账号、非回环地址必须认证。

规则只在服务端执行。Web 不重复写校验，只做必填提示；保存或测试失败时读取服务端返回的 `VALIDATION_ERROR`，按 `path` 把消息显示到对应字段下，并用 `aria-describedby` 关联。Web 不能导入含 `node:net` 的校验包（例如直接复用服务端的 host 判断），否则浏览器构建会失败。

**防止密码外泄（重要）：** 保存或测试时不填密码就沿用已存密码，这只在 `host` 和 `username` 都没变时允许。这两项变了必须重新输入，否则任何管理员都能把服务器改成自己的主机，把已存密码发出去。

**防止探测内网：**

- 端口只允许 25、465、587、2525。
- 生产环境拒绝回环地址和 `不加密`；开发环境保留，Mailpit 要用。
- 测试接口按管理员限频，每分钟 5 次。
- 只返回错误分类（复用 `classifySmtpError`：认证失败、连接失败或超时、被拒收），不返回服务器响应。
- 超时用 `SMTP_TIMEOUT_MS`。

**日志与审计：**

- 新操作日志 `mail_settings_update` 记录改了哪些字段。密码只记“已更改”，不记内容，也不记密文。
- 新操作日志 `mail_settings_test` 记录收件人和结果分类。
- 确认 API 请求日志不记录请求体，并加测试：密码不出现在日志、响应和操作日志里。

## 页面

按设计稿实现。**全部用 shadcn/ui 原生组件，不写自定义组件**（用户 2026-11-05 决定）。

| 位置                 | 组件                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| 三个标签             | `Tabs`（已有）                                                        |
| 启用开关             | `Switch`（用 shadcn CLI 新增）                                        |
| 服务商、加密方式     | `ToggleGroup`，单选（用 shadcn CLI 新增）。不用项目自写的 `Segmented` |
| 输入框和标签         | `Input`、`Label`（已有）                                              |
| 卡片、提示、发送状态 | `Card`、`Alert`、`Badge`（已有）                                      |
| 按钮、测试邮件弹窗   | `Button`、`Dialog`（已有）                                            |

设计稿只表达布局和状态，控件的外观以 shadcn 组件为准。告警设置标签的现有表单不在本次范围，继续用现有的 `Segmented` 和 `RecipientsInput`。

- 三个标签：`告警列表`、`告警设置`（现有表单不变）、`邮箱设置`。路由 `tab=settings` 继续指向告警设置，旧链接不失效；新增 `tab=mail`。
- 告警设置页的“未配置”警告加链接“去邮箱设置”。
- 选 QQ 邮箱时填入 `smtp.qq.com`、465、隐式 TLS，发件人跟随账号。
- 生产环境不显示“不加密”选项。
- 已保存的密码显示“已设置”和“更改”按钮，页面拿不到密码。
- 右侧“发送状态”显示配置来源、最近成功发送、最近测试、等待发送封数。手机上排到表单下面。
- 测试成功的提示要写明“服务器已接受，请确认真的收到了”，因为 SMTP 接受不等于送达。

**发送状态：**

| 状态     | 条件                                 |
| -------- | ------------------------------------ |
| 未配置   | 没有有效配置                         |
| 已停用   | `managed` 且未启用                   |
| 正常     | 有有效配置，且最近没有连续发送失败   |
| 发送失败 | 有有效配置，发件箱最新一次结果是失败 |
| 需要处理 | 已保存的密码无法解密                 |

| PR  | 内容                                                                      |

| 1   | 新包 `packages/mailer`：把传输、错误分类、校验从 Worker 移出来，行为不变  |
| 2   | 迁移、加密、数据库读写、操作日志枚举                                      |
| 3   | Worker 每轮读配置，按“配置来源”表选择                                     |
| 4   | API 三个接口和全部安全规则                                                |
| 5   | 页面、标签、视觉对照、e2e；手册、`.env` 示例、`bootstrap-server.sh`、部署 |

把传输移到新包是因为测试接口要从 API 发信，而 API 不能依赖 `apps/worker`。

## 验收

1. 升级后不做任何操作，发信行为不变。
2. 页面保存后，下一轮发信就用新配置，不用重启。
3. 停用后邮件留在发件箱；重新启用后发出。
4. 密码不出现在响应、日志和操作日志里，数据库里只有密文。
5. 改了 `host` 或 `username` 却不填密码时，保存和测试都被拒绝。
6. 解不开密码时不发信，不回退，页面有提示；重新填写后恢复。
7. 两人同时保存时，后保存的收到 409。
8. 用真实 QQ 邮箱发一封测试邮件并确认收到。

## 上线步骤

1. 部署前在 `app.env` 添加 `SETTINGS_ENCRYPTION_KEY`，并离线保存一份。
2. 发布、迁移。
3. 在页面填写配置，发测试邮件确认收到，再保存。
4. `notify.sh` 仍读 `app.env` 的 `SMTP_*`，运行 `set-smtp.sh` 或手工配置，并用 `notify.sh --subject 测试` 确认。

## 风险

- **两处配置：** 换邮箱时只改页面，数据库宕机时的告警仍走旧账号，可能发不出。手册和页面都写明，上线检查清单加一条。
- **新增一个要保管的密钥：** 丢失后要重填 SMTP 密码，不影响其他数据。
- **管理员权限变大：** 改发件服务器后，管理员能决定系统邮件经过哪台服务器，邮件内容包括账单和告警。这是决定 3 接受的取舍，靠操作日志追溯。
