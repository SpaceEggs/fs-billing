# 呼入话单设计

本文档写于 2026-11-05。来电要有话单，话单页要能按呼入、呼出筛选，详情要显示方向。呼入**暂时不收费**；运营商的跨国来电收费规则还待用户确认，所以设计要留得住以后加费率。

## 已决定（用户，2026-11-05）

| #   | 问题           | 决定                                                                   |
| --- | -------------- | ---------------------------------------------------------------------- |
| 1   | 号码归属       | 写在 FreeSWITCH 的来电路由里（`billing_tenant`），和现在开户的做法一致 |
| 2   | 客户门户       | 显示呼入话单                                                           |
| 3   | 账单           | 呼入不进费用合计，明细里能查到                                         |
| 4   | 余额不足或停用 | 来电照接：不走授权                                                     |

## 数据

`cdrs` 加 `direction text NOT NULL DEFAULT 'outbound' CHECK (direction IN ('outbound','inbound'))`，老话单都是呼出。

`cdrs_answered_shape` 现在要求接通的话单有 `matched_prefix`、`country`、`rate`。改成只对呼出要求；呼入这三项为空，`charge = 0`，`billed_minutes = 0`。

## 话单入库

- FreeSWITCH 在呼入通道上设 `billing_direction=inbound`，同时设 `billing_tenant` 和 `billing_dialed_number`（被叫的线路号码）。
- Worker 读 `billing_direction`。缺失或其他值都按呼出处理，老的 FreeSWITCH 配置不受影响。
- 呼入话单不查费率，不进扣费队列，不写流水，也不进对账。
- `call_uuids` 去重照旧，重推不会产生第二条。
- 租户编码不对的呼入话单和呼出一样进未归属待办。
- 未接来电也有话单，时长 0。
- `caller` 是对方号码，`callee` 和 `billing_number` 是线路号码。

## 统计和账单

所有“消费”“费用”合计本来就按 `charge` 算，呼入是 0，不受影响。**按通话数、通话时长统计的地方只算呼出**，否则门户和账单上的用量会变大；这些地方要逐一确认并加测试。

账单明细和导出里能看到呼入，金额 0。

## 页面和接口

- 管理端和门户的话单接口加可选参数 `direction`（`inbound`、`outbound`，不传表示全部）。导出同样支持。
- 响应加 `direction` 字段，CSV 加“方向”列，放在现有列之后，不打乱旧列的顺序。
- 筛选用 shadcn `ToggleGroup`：全部、呼入、呼出。话单列表和详情都显示方向，用 `Badge`。
- 呼入行的费率、费用显示 `—`，不显示 0.3 之类的费率。

## 以后加费率

有了方向字段后，加呼入费率只需要：入库时查费率、入扣费队列。今天的呼入话单是 0 元，加费率后不回算。

## 上线步骤

先部署代码和迁移，再改 FreeSWITCH 的 `trunk_inbound.xml`：去掉 `process_cdr=false`，加上三个变量。顺序不能反，否则旧 Worker 会把呼入当呼出处理，因为没有费率而进未归属待办。
