# FS-Billing 设计文档

> 版本：v0.1（2026-09-29）
> 状态：业务与架构已确认，部分细节待定（见 [plan.md](plan.md) 中各阶段的待定验收项）

---

## 1. 背景与目标

现有 VOS2009 对接运营商 SIP Trunk 并转售给客户，但不支持客户自助查账，也不支持 TLS 注册、SRTP 等新功能。

新建一套 **FreeSWITCH + 自研计费系统**：

- FreeSWITCH：负责 SIP 接入、TLS/SRTP、路由到上游运营商
- 计费系统（本项目）：负责话单采集、计费、余额、账单，以及客户查账门户和管理后台

新系统只服务新客户，**不导入 VOS 历史数据**，从零开始。

## 2. 功能范围

### 2.1 第一版要做的

| 模块 | 功能 |
|---|---|
| 客户门户 | 查看余额、话单、月账单、余额流水；导出 CSV |
| 管理后台 | 租户管理、费率表配置、充值/赊账/调账、待收款、账单、未归属话单、余额提醒设置 |
| 与 FreeSWITCH 集成 | 接收话单、呼叫前授权（余额与费率检查） |
| 通知 | 余额提醒邮件、停机通知邮件、系统故障告警邮件 |

### 2.2 明确不做的

- SIP 账号、IP 对接、路由的管理（全部在 FreeSWITCH 上配置）
- 在线支付（只有管理员手动充值）
- 多语言（只用中文）
- 双重验证（2FA）
- 按租户设置故障策略
- 上游运营商成本与利润统计
- 汇率换算

## 3. 系统架构

### 3.1 服务器

**两台 Debian 服务器，放在同一机房，走内网通信。**

| 服务器 | 运行内容 | 理由 |
|---|---|---|
| 服务器 A | FreeSWITCH | 语音质量不受计费系统负载影响 |
| 服务器 B | 计费系统（Docker Compose） | 网站对公网开放，被攻破也无法控制交换机 |

计费系统服务器初期配置：2 核 4G 起步。

### 3.2 计费系统组成

```
                        ┌─────────────────────────── 服务器 B ───────────────────────────┐
                        │                                                                 │
  客户/管理员浏览器 ─HTTPS─▶ 反向代理 (Caddy) ──┬─▶ Web（网页）                           │
                        │                       └─▶ API（/api）──┐                       │
                        │                                         ▼                       │
                        │                                    PostgreSQL                   │
                        │                                         ▲                       │
  服务器 A ───内网────────────────────────────────▶ Workers ─────┘                       │
  FreeSWITCH            │                          ├─ 接收话单                            │
  ① 呼叫前授权查询       │                          ├─ 呼叫授权接口                         │
  ② 话单推送            │                          ├─ 计费扣费                            │
                        │                          ├─ 月账单生成                          │
                        │                          └─ 邮件提醒与告警                       │
                        └─────────────────────────────────────────────────────────────────┘
```

| 程序 | 职责 | 对外开放 |
|---|---|---|
| **Web** | 客户门户和管理后台的界面，不直接访问数据库 | 公网（HTTPS） |
| **API** | 登录、权限、数据查询与修改 | 公网，与 Web 同域名，路径 `/api` |
| **Workers** | 面向 FreeSWITCH 的接口（话单、授权）+ 后台任务 | **仅内网**，只允许 FreeSWITCH 服务器访问 |

面向 FreeSWITCH 的接口放在 Workers 而不是 API，这样**网站和 API 的故障或重启不会影响通话和话单采集**。

## 4. 与 FreeSWITCH 的集成

### 4.1 租户标签

在 FreeSWITCH 上，给每个客户的 SIP 账号或 IP 对接设置通道变量：

```
billing_tenant=<租户编码>     例：billing_tenant=ABC001
```

- 租户编码在管理后台新建租户时填写，**两边必须完全一致**
- 计费系统只认租户编码，不关心 SIP 账号、IP 等细节

### 4.2 呼叫前授权

每通外呼在桥接到上游之前，FreeSWITCH 先调用 Workers 的授权接口。

**请求**：租户编码、规范化计费号码 `callee` 与原始拨号 `dialedNumber`、通话 UUID，可选的 `billingNumber` 投影。新协议以 `dialedNumber` 区分原始拨号和旧版已规范化号码。

**计费系统的判断逻辑**：

0. 调用 `packages/rating/src/dialed.ts` 的 `resolveBillingNumber`。从原始拨号归一化，核验 `callee` 和可选投影。格式错误返回 HTTP 400，使用 SIP 484；号码不一致单独记录错误并返回 HTTP 503。
1. 租户不存在或已停用 → 拒绝
2. `billing_number` 匹配不到费率 → 拒绝
3. 可用金额 = 余额 + 透支额度
4. 可打分钟数 = 可用金额 ÷ 每分钟费率，向下取整
5. 可打分钟数 ≤ 0 → 拒绝
6. 否则放行，最长时长 = 可打分钟数 × 60 秒

**FreeSWITCH 的处理**：

| 授权结果 | 处理 |
|---|---|
| 放行，最长 N 秒 | 接通后设定时器，N 秒后自动挂断 |
| 拒绝 | 不外呼，返回相应的 SIP 错误码 |
| **超时（1.5 秒）或无响应** | **放行，最长 1800 秒（30 分钟）**，并设置变量 `billing_unverified=true` 写入话单 |

号码规则已于 2026-10-13 确定。客户带 `+` 或 `00` 拨号时视为国际号码，只去掉该国际冠字。没有国际冠字时视为国内号码，加 `86`；国内固话先去掉一个开头的 `0`。不能根据首位数字猜测国际号码。

| 原始拨号 | `billing_number` | 上游收到的号码 |
|---|---|---|
| `+447700900123` | `447700900123` | `+447700900123` |
| `00447700900123` | `447700900123` | `00447700900123` |
| `13800138000` | `8613800138000` | `13800138000` |
| `07551234567` | `867551234567` | `07551234567` |
| `+13055551234` | `13055551234` | `+13055551234` |
| `13055551234` | `8613055551234` | `13055551234` |

桥接保留原始 `destination_number`，不做号码改写。路由号码只接受一个可选的开头 `+` 和 1–17 位 ASCII 数字，拒绝 `|`、`,`、空格等字符，返回 SIP 484。17 位上限允许 `00` 加 15 位国际号码；计费号码另行要求首位为 1–9、总长 6–15 位。E.164 的 15 位限制只作用于 `billing_number`，不能拿来截断或改写上游号码。

Worker 是号码归一化的权威。授权与 CDR 都调用同一个 `resolveBillingNumber`，使用规范化结果匹配费率并保存到数据库。Lua 仅为请求前校验和授权超时放行生成同规则投影，在脚本开始时设置 `billing_dialed_number`，校验后设置 `billing_number`。提前返回的话单也保留原始拨号。Worker 从原始拨号重新计算，拒绝不一致的投影；Lua 要求授权成功响应包含一致的号码，缺失或不一致均返回 SIP 503。这样不会仅凭 Lua 的结果收费，也不会让授权和话单分别维护归一化逻辑。Worker 故障时原始拨号与投影仍随话单落盘，恢复后由同一函数重新核验。

话单的 `callee` 保存原始拨号，`billing_number` 保存费率与账本使用的国际号码。解析优先使用 `billing_dialed_number`，避免 FreeSWITCH 的 `execute_extension` 改变展示号码。有效的未归属话单也保存规范化号码；号码格式无效时该列为 NULL；投影不一致时保存 Worker 计算的号码，以独立原因停放并记录告警。扣费备注为 `通话扣费 <UUID> <billing_number>`。

只接受包含原始拨号的号码格式。授权缺少 `dialedNumber` 返回 HTTP 400、SIP 484、`号码格式错误`。CDR 缺少 `billing_dialed_number` 按话单校验失败进入未归属待办并告警，不计费。

迁移 `0004_billing_number_not_null` 将正式话单的 `billing_number` 设为非空，格式约束统一为首位非零的 6–15 位数字。未归属话单仅在 `号码格式错误` 或 `话单校验失败: ...` 时允许且要求 NULL，因为这两类输入没有可信计费号码。其他原因必须保存计算后的号码。业务写入仍先执行 `lock_tenants`，不增加业务锁，分区只在维护路径创建，重试保留在最外层，金额继续由 decimal.js 计算。

> "未经验证"标记**只在管理后台显示**，客户门户中不显示，也不向客户透露计费系统故障信息。这些话单对客户照常计费。

### 4.3 话单推送

- 使用 `mod_json_cdr`，每通电话结束后 HTTP POST 到 Workers
- 推送失败时 FreeSWITCH 落盘保存并重试，**保证话单不丢失**
- 同一通电话被重复推送时，按通话 UUID 去重，**不会重复扣费**

### 4.4 接口安全

- Workers 的 FreeSWITCH 接口只监听内网地址
- 只允许 FreeSWITCH 服务器的 IP 访问
- 请求需携带共享密钥

### 4.5 FreeSWITCH 侧的配套要求（不属于本项目，但必须配置）

- 每个租户设置**并发上限**：计费系统故障时，这是控制透支的主要手段
- 配置 TLS 注册与 SRTP

## 5. 计费规则

| 项目 | 规则 |
|---|---|
| 计费时长 | 从**接通**开始算，振铃不计费 |
| 计费周期 | **60/60**：不满一分钟按一分钟（例：3:10 和 3:50 都按 4 分钟） |
| 计费公式 | 费用 = 计费分钟数 × 每分钟费率 |
| 未接通 | 不收费 |
| 其他费用 | 无月租、无接通费 |
| 计费时间点 | 按**接通时间**确定使用哪个时刻生效的费率，以及归属哪一天、哪个月 |

计费周期作为**可配置参数**存储（默认 60/60），以后支持 6/6、1/1 时无需改程序。

**计费示例**（费率 0.1000 元/分钟）：

| 通话时长 | 计费分钟 | 费用 |
|---|---|---|
| 0:00（未接通） | 0 | 0.00 |
| 0:01 | 1 | 0.10 |
| 3:10 | 4 | 0.40 |
| 3:50 | 4 | 0.40 |
| 4:00 | 4 | 0.40 |
| 4:01 | 5 | 0.50 |

## 6. 费率

### 6.1 结构

- **每个租户一张独立的费率表**
- 每张表包含若干条：前缀、国家/备注、每分钟费率
- 规模：每张表约几百条
- 费率精度：**4 位小数**

### 6.2 匹配规则：最长前缀优先

| 被叫号码 | 候选前缀 | 使用 |
|---|---|---|
| 1876xxxxxxx | `1`、`1876` | `1876`（牙买加） |
| 447xxxxxxxx | `44`、`447` | `447`（英国手机） |

匹配不到任何前缀 → 呼叫前授权直接拒绝。

### 6.3 生效时间

- 调价时可以指定生效时间（例：2026-10-01 00:00 北京时间起）
- 每通电话按**接通时刻**有效的费率计费
- 历史话单和已生成的账单不受调价影响

### 6.4 管理操作

- **CSV 导入**：格式为 `prefix,country,rate`；有任何一行出错，整个文件不导入，并提示出错的行号和原因
- **CSV 导出**
- **复制费率表**：以某个租户的费率表为模板，建立新租户的费率表
- 导入时校验：前缀只能是数字、不能重复、费率不能为负、小数不超过 4 位

## 7. 余额与流水

### 7.1 原则

- 余额**只存在计费系统**，FreeSWITCH 不保存余额
- **每一笔变动都记成一条流水**，余额等于所有流水的合计
- 流水只能新增，不能修改或删除；改错了用一笔反向的"调账"来冲正

### 7.2 流水类型

| 类型 | 方向 | 说明 | 收款状态 |
|---|---|---|---|
| 充值 | + | 客户已付款 | 已收款 |
| 赊账充值 | + | 先加余额，客户稍后付款 | 待收款 → 管理员确认后变为已收款 |
| 赠送 | + | 促销、补偿 | — |
| 调账 | + / − | 修正错误，必须填写原因 | — |
| 通话扣费 | − | 话单计费后自动产生 | — |

每笔人工操作记录：操作管理员、操作时间、原因备注。

### 7.3 备注的可见性

- 充值、赠送、调账的备注**对客户可见**，显示在客户门户的余额流水中
- 赊账充值的备注仅内部可见，客户看到的是"账户充值"

### 7.4 透支额度

- 每个租户可单独设置
- 默认值：**CNY 100 元 / USD 15 美元**
- 余额 + 透支额度 ≤ 0 时，新呼叫被拒绝（停机）

### 7.5 已知限制（第一版接受）

同一租户同时发起多通电话时，每通电话都按当时的全部可用金额授权，可能导致超出透支额度。第一版依靠透支额度和 FreeSWITCH 并发上限来控制；后续版本可增加"通话中冻结金额"机制。

## 8. 通知与告警

所有通知都通过**邮件**发送（需要提供 SMTP 账号）。

### 8.1 余额提醒（按租户设置）

| 设置项 | 说明 |
|---|---|
| 提醒阈值 | 余额低于此数值时提醒 |
| 通知邮箱 | 可填多个，默认只填管理人员邮箱 |

| 触发时机 | 邮件 |
|---|---|
| 余额降到阈值以下 | 发一封"余额不足"提醒；回到阈值以上后，下次再降下来才会再发 |
| 余额 + 透支额度用完 | 发一封"已停机"通知 |

### 8.2 系统故障告警（发给管理员）

- 触发条件：FreeSWITCH 授权请求超时、话单处理失败等
- **合并发送**：故障开始时发一封，持续期间每 N 分钟汇总一封，恢复后发一封恢复通知

## 9. 月账单

- 按北京时间的自然月统计
- 内容：期初余额 + 充值 + 赠送 ± 调账 − 通话扣费 = 期末余额，以及按国家、按日汇总的通话量和金额
- "充值"包含赊账充值，对客户不区分
- 客户在门户查看，并可导出 CSV

## 10. 账号与权限

| 角色 | 说明 |
|---|---|
| 管理员 | 登录管理后台，可查看和操作所有租户 |
| 客户 | 登录客户门户，只能看到自己租户的数据 |

- 第一版每个租户开一个门户账号（数据库支持多个账号，以后可放开）
- 客户忘记密码时由管理员在后台重置
- 不做双重验证

## 11. 租户隔离与安全

1. **每张业务表都带租户编号**
2. **API 只根据登录身份确定租户**，永远不信任网址或请求参数里传来的租户编号
3. **PostgreSQL 行级安全（RLS）兜底**：即使 API 代码漏写过滤条件，数据库也不会返回其他租户的数据
4. **自动越权测试**：每次改代码都会自动测试"用 A 的账号访问 B 的数据"，必须失败

## 12. 时间、币种与格式

| 项目 | 规则 |
|---|---|
| 时区 | 数据库内部存 UTC（`timestamptz`），界面显示与统计全部按**北京时间** |
| 日期归属 | 按接通时间；跨午夜的电话归入接通当天 |
| 币种 | 每个租户一个币种（CNY 或 USD），余额、费率、账单都用该币种，不做换算 |
| 费率精度 | 4 位小数 |
| 金额精度 | 显示 2 位小数；计费过程中不提前四舍五入 |
| 金额存储 | 数据库 `NUMERIC`，代码 `decimal.js`，**禁止浮点数** |

## 13. 数据保留

### 13.1 话单永久保存

- 话单**默认永久保存**，系统不会自动清理
- 只有**管理员**可以在后台手动删除，客户在门户中无法删除
- 删除方式：选择租户 + **整月**范围，二次确认（需输入租户编码）后执行
- 只能删除**已生成月账单**的月份，当月不可删除（否则该月账单将无法生成）
- 每次删除都记入操作日志：谁、何时、删除了哪个租户哪段时间的多少条话单

### 13.2 删除话单不影响账务

话单删除后，**余额流水和月账单保留不变**：

- 余额流水中的通话扣费仍然存在，余额不会因此改变
- 已生成的月账单仍然可以查看，但无法再导出该时段的话单明细
- 已删除时段的月账单**不能重新生成**

这样可以保证账目始终能对上，不会因为删除明细而出现"余额和账单对不上"的情况。

### 13.3 存储与性能

以每天 1 万通电话估算：

| 数据 | 每年约 |
|---|---|
| 整理后的话单（用于查询和计费） | 2 GB |
| FreeSWITCH 推送的原始 JSON | 20 GB |

- 话单表**按月分区**存储，数据量增长后查询速度不受影响
- 原始 JSON 超过 6 个月后压缩存档，需要时可恢复；整理后的话单始终保留在数据库中

## 14. 其他约定

| # | 事项 | 结论 |
|---|---|---|
