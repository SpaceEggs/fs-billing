# 同机测试环境（2026-11-05）

FreeSWITCH 与计费系统装在同一台阿里云服务器上，用于接 SIP trunk 做内部测试。**这不满足设计的双机要求，也不是阶段 10 验收证据**；接真实客户前要拆开。真实地址和密钥不在仓库里。

## 和手册不同的做法

- Worker 只监听回环，`WORKER_ALLOWED_IPS=127.0.0.1`，授权、话单 relay 和时钟心跳都走本机。
- 防火墙在 B 的规则上加了 SIP 和 RTP。SIP 只放行指定来源，RTP 开放。重跑 `bootstrap-server.sh` 会覆盖这些规则。
- 域名用 certbot 签发，`app.env`、`owner.env` 的站点地址和 `monitor.env` 的证书路径都改成了域名。
- 配置备份加上了 `/etc/letsencrypt` 与 `/etc/freeswitch`。
- 在 `/etc/freeswitch/dialplan/` 加了同机模拟上游：一个只绑内网 5090 端口的 profile，接通后回声，尾号 486 回忙，480 回无人接听。模拟上游的通道设 `process_cdr=false`，不产生话单。

## 同机验证结果

用 SIPp 带摘要认证打真实 SIP 通话，经过 FreeSWITCH、Lua 授权、话单 relay、Worker 和扣费队列，上游是模拟的。**还没有接真实 trunk，也没有用真实话机打过。**

| 场景                           | 结果                                     |
| ------------------------------ | ---------------------------------------- |
| 正常接通                       | 话单入库，按分钟进位扣费，账本与余额一致 |
| 被叫忙（486）、无人接听（480） | 客户端收到对应错误码，不扣费             |
| 没有费率的号码（+44）          | 返回 404，不扣费                         |
| 密码错误                       | 未接通                                   |

## 发现的问题

1. **挂断延迟多计时长（已在服务器修复，已写入 README）。** 缺少 `rtp-timer-name=soft` 时，BYE 延迟约 5 秒才响应，每条腿都多等，话单结束时间推迟。
2. **仓库的拨号计划没有并发上限。** 设计把 `limit` 当作 Worker 故障时控制透支的主要手段，但 `billing.xml` 里没有这一步。测试服务器上已手工加入，尚未进仓库。这一步本身还没有专门测试过。
3. **无人接听的话单挂断原因不准。** 客户端收到 480，但 A 腿话单是 `NORMAL_CLEARING`，因为拨号计划最后的 `hangup NORMAL_CLEARING` 盖掉了原因；486 能保留为 `USER_BUSY`。这会影响后台排查。
4. **同一 FreeSWITCH 的入站腿会产生话单。** 模拟上游的入站腿没有计费变量，进了未归属待办并触发 `cdr_failed` 告警。接真实 trunk 后，如果允许来电进入同一实例，要确认不会重现。
