# QQ 邮箱 SMTP 手工核实（阶段 9 PR 2）

状态：**待实测**。本文件只是操作手册和结果登记表，PR 2 没有连接过真实的 QQ 邮箱。由负责人在测试服务器上执行，把结果填进各处「待实测」，并把脱敏后的命令输出放在本目录。

设计依据：[phase-9-design.md 的「配置」一节](../../phase-9-design.md#配置)里 QQ 邮箱的 7 个待核实点，以及「本地与 CI 测试」一节最后一条（真实 QQ 账号的发送不进 CI，只做一次手工核实）。

## 红线

- 授权码只放在服务器的环境文件里（`/etc/fs-billing.env`，以及 `/opt/fs-billing/.env`，权限 600，属主为服务用户）。**不要**写进命令行参数、shell 历史、本目录的任何文件、PR 或聊天记录。
- 输出里出现的邮箱地址和授权码相关字样，贴进证据前先脱敏。`mail:test` 本身不打印授权码，也不重复打印收件人地址。
- 发送节奏要克制：下面第 3 项会测试频率上限，先小批量，遇到限流响应就停。
- 授权码若曾出现在聊天或截图里，核实完成后在 QQ 邮箱设置中重新生成一个，并更新两份环境文件。

## 前置

1. QQ 邮箱设置里已开启 SMTP 服务，并生成授权码（不是登录密码）。
2. 服务器出站 465 端口可达：`nc -vz smtp.qq.com 465`。
3. 两份环境文件里写好下列键（值的来源见上一条；`MAIL_FROM` 必须与 `SMTP_USER` 相同，否则配置校验会拒绝启动）：

   ```
   SMTP_HOST=smtp.qq.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=pbx3cx@qq.com
   SMTP_PASS=<授权码，只在服务器上填写>
   MAIL_FROM=pbx3cx@qq.com
   ```

4. 代码已部署到 `/opt/fs-billing`，并完成下面的「部署步骤」。

## 部署步骤（PR 2 上线前）

按顺序执行，每一步成功再做下一步（部署的通用步骤见阶段 10 运维手册，这里只列 PR 2 特有的）：

1. `pnpm install --frozen-lockfile`：PR 2 新增依赖 `nodemailer@10.1.1`，漏掉会让 Worker 启动时找不到模块。
2. `pnpm db:migrate`：迁移 0021 建 `email_outbox` 与 `balance_alert_deliveries.outbox_id`。
3. `pnpm --filter @fs-billing/worker queue:migrate`：建 `notify-tick` 队列。**必须在重启 Worker 之前**，运行时应用角色不能建队列，漏掉会让 Worker 在 `boss.work` 时启动失败。
4. 在两份环境文件里写好 `SMTP_*` 与 `MAIL_FROM`（见前置第 3 条），然后在**重启服务之前**校验配置的一致性规则能通过：运行一次 `mail:test`（下一节），它与 Worker 启动共用同一套校验，配置有误会立刻报错并指出是哪个键（不回显取值）。常见的一致性规则：`MAIL_FROM` 必须等于 `SMTP_USER`（QQ 邮箱）、465 必须 `SMTP_SECURE=true`、`SMTP_USER` 与 `SMTP_PASS` 同有或同无、有账号必须有主机。
5. 重启 `fs-billing-worker`，确认日志里没有「未设置 SMTP_HOST」的告警，`select name, cron from pgboss.schedule` 里有 `notify-tick`。

## 执行方式

在服务器上以服务用户运行，环境从环境文件读取，不经过命令行：

```
cd /opt/fs-billing/apps/worker
sudo -u fs-billing node --env-file=/etc/fs-billing.env --import tsx scripts/mail-test.ts --to <收件地址>
```

（开发机上等价于 `pnpm --filter @fs-billing/worker mail:test -- --to <收件地址>`，读 `.env`。）

输出示例（成功）：`发送成功：smtp.qq.com:465（隐式 TLS），接受 1 个收件人，拒绝 0 个，用时 … ms`，再一行服务器响应首行。失败时输出分类：可重试 / 认证失败 / 永久失败，加响应码与首行（地址已抹掉）。退出码 0 成功，1 失败。

## 失败后的补发

`failed` 的邮件不会自动再试（例如撞到每日额度后用尽了重试次数）。额度恢复后：

```
sudo -u fs-billing node --env-file=/etc/fs-billing.env --import tsx scripts/mail-requeue.ts --since 2026-10-29
```

`--id <uuid>` 只放回一封；`--since` 接受带时区的时间或 `YYYY-MM-DD`（按北京时间）。只改 `failed` 的行，次数清零，下一分钟的 `notify-tick` 重新发送。
