## 经 HTTP 的耗时

PR 3 没有做这项（见其「与设计的差异」第 9 条）。plan 对月账单端点没有性能验收标准，下面只记录数字，不判断通过与否。

[statement-http-timings.txt](statement-http-timings.txt) 是 `apps/api/scripts/statements-perf-http.ts` 的完整输出（各次样本的原值都在里面）。传输与 PR 3 的 [`ledger-perf-http.ts`](../../../apps/api/scripts/ledger-perf-http.ts) 相同：同进程起 Fastify 应用监听 `127.0.0.1`，Node `fetch` 走回环 HTTP，真实 cookie 网关（`auth.session` 里插入会话），业务查询用 `fs_billing_app` 角色，响应体读完并用共享契约解析。每项 2 次预热加 7 次测量，取中位数。

**数据库。** 阶段 6 的性能库 `fs_billing_perf_pr3_uuid_v4` 只迁移到 0015（缺 0016、0017）。这里用它的副本，原库没有改动：

```sh
docker exec fs-billing-postgres-1 psql -U fs_billing -d postgres \
  -c "create database fs_billing_perf_p7 template fs_billing_perf_pr3_uuid_v4 owner fs_billing"
# 只迁移副本（DATABASE_URL、APP_DATABASE_URL、AUTH_DATABASE_URL 三个都指向 fs_billing_perf_p7）
pnpm db:migrate
cd apps/api
PERF_TARGET_DATABASE=fs_billing_perf_p7 PERF_ROUNDS=7 \
  PERF_OUTPUT=../../docs/evidence/phase-7/statement-http-timings.txt \
  node --env-file-if-exists=../../.env --import tsx scripts/statements-perf-http.ts
```

副本含 `PORTALBIG`（300 万话单，2025-10 至 2026-10-17，285 万笔流水，2026-09 北京月 234,277 通）与另外 16 个租户，18 条迁移。脚本只接受 `fs_billing_perf_p7`，先删掉旧夹具的 48 行账单（只有头部、没有明细），再用 Worker 的路径（`listMissingStatements` 加 `withSystem` 的 `repeatable read` 里的 `generateStatement`）补出除 PORTALBIG 2026-09 之外的全部月份（57 张），最后在副本里为 PORTALBIG 新建门户账号与会话。性能库的数据截止 2026-10-17，运行日是 2026-10-22，所以 2026-10 进行中月份的实时数字只到 10-17。
